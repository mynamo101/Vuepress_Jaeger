::: tip 關於 Work Unit

在開始認識每個區塊和元素之前，一定要先瞭解Work Unit的概念Work Unit就像是Wwise專案中的「資料夾」，它用來組織和管理所有的聲音和事件。每個Work Unit可以包含多個聲音對象（Sound Object）、事件（Event）以及其他相關的設定。這樣的結構讓我們能夠更有效率地管理大量的音效資源，並且方便團隊協作。
:::

## 🧠 Work Unit 基本概念
在官方的說法中Work Unit透過Xml的結構來儲存專案中的各種元素，讓同一個專案可以被多人同時編輯，而不會產生衝突。

跟FMOD的Event管理界面類似，在FMOD中并沒有`Work Unit`的概念，所有Event都是平鋪在一個列表中，如果要分類管理不同的 Event，我們需要透過資料夾來組織它們。而 Wwise 的`Work Unit`則是內建的分類系統，讓我們可以更方便地管理和組織音效資源。


### 結構層級
而Wwise不同的地方在於：如果要管理專案中的聲音和事件，我們需要使用`Work Unit`來進行分類和組織。
在Project Explorer中，最高的第一層級是三個資料夾：

![alt text](/Images/Course/Wwise/Intro/004_ProjectExplorer.png)

::: file-tree icon="colored" title="Wwise Project Explorer"
- Devices/
  - **Default Work Unit.wwu**
    - No_Output
    - System
- Busses/
  - **Default Work Unit.wwu**
    - Master Audio Bus
- Containers/
  - **Default Work Unit.wwu**
    - 我們之前建立的Sound SFX的位置
  - Factory_Soundseed_Air_Objects.wwu
  - Factory_Synth_One.wwu
:::

 - Devices：用來管理音訊輸出裝置的設定
 - Busses：用來管理音訊匯流排（Bus）的設定
 - Containers：用來管理聲音對象（Sound Object）和事件（Event）的設定

在這三個資料夾下都有一個叫做 `Default Work Unit.wwu` 的檔案，這就是我們的 Work Unit。我們可以根據需要來重新命名，或者新增更多的 `Work Unit` 來分類不同類型的聲音和事件。

::: info 和 FMOD 差異在哪？

 - 在FMOD中，比較沒有太複雜的層級關係，如果要管理大量的Event，我們只要用資料夾來分類即可。
 - 在Wwise中，我們需要使用Work Unit來進行分類和組織，也可以在Work Unit內部建立子資料夾進一步分類。
:::

>[!IMPORTANT]
>Work Unit 可以被視為一個「資料夾」，所以可以在一個Work Unit底下再新建一個Work Unit，形成多層級的結構，甚至可以在Bus底下建立Work Unit來管理不同的Bus。
