Profiler 讓我們看到背後的 Voice、CPU、Memory、參數流動與載入行為，避免憑感覺盲修。建立資料驅動的音頻調整流程。

## 🎯 本節你會收穫
- 🔌 理解 Remote 連線流程與前置需求
- 👁️ 熟悉 Voice Monitor / Advanced Profiler / RTPC Monitor / States 面板用途

## 一、連線
在遊戲端整合後（Unity / Unreal / 自研）啟動 → Wwise Authoring → Remote 接上對應 IP / 埠。

## 二、主要視圖
| 視圖              | 功能                          |
| ----------------- | ----------------------------- |
| Voice Monitor     | 當前活躍聲音與生命週期        |
| Advanced Profiler | CPU / Memory / Streaming 分析 |
| RTPC Monitor      | 參數即時變化曲線              |
| States / Switches | 全域與物件狀態觀察            |
| Log               | 載入 / 失敗 / Warning 資訊    |

## 三、典型問題排查（速查表）
| 問題     | 排查順序                         | 工具                        | 可能修正                                   |
| -------- | -------------------------------- | --------------------------- | ------------------------------------------ |
| 事件無聲 | Log → Event 結構 → Bank 載入     | Log / Event Viewer          | 確認 Bank 載入順序（Init 先）              |
| 參數不動 | 遊戲側送值？名稱一致？範圍？     | RTPC Monitor                | 改更新頻率 / Clamp / 名稱對齊              |
| 聲音爆量 | 哪種類型堆疊？                   | Voice Monitor               | 設 Max Instance / Priority / Virtual Voice |
| CPU 峰值 | Decode / Effects / Voices 哪塊？ | Advanced Profiler           | 換格式 / 減 Reverb / 降並發                |
| 偶發延遲 | Streaming Queue 堵？             | Advanced Profiler Streaming | 增緩衝 / 預讀關鍵檔                        |

## 四、Systematic Debug 流程（建議）
1. 定義問題：聽感 / 時間戳 / 場景條件
2. 連線 Profiler（保持同版本資源）
3. 重現並標記時間（寫在日誌）
4. Voice / CPU / Memory 同步截圖或匯出
5. 找出首要瓶頸 → 制定單一改動 → 回測
6. 記錄「前後差值」避免主觀幻覺

## 五、最佳實務 Tips
- 先鎖最大 Voices，再看是否需要再優化素材或架構
- 遠距 / 次要循環聲：提早 Virtual，保留邏輯不浪費混音
- 參數抖動：觀察 RTPC 更新頻率，必要時程式端節流
- 音樂過多轉場耗效能：合併無需即時分離的 Layer
