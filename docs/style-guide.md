# Wwise 系列文章寫作規範（Style Guide）

> 目的：確保所有課程 / 教學文風格一致、易讀、易維護，並利於後續自動檢查（lint:lessons）。

## 1. Frontmatter 必備欄位
| Key | 說明 | 範例 |
| --- | ---- | ---- |
| title | 文章標題 | Random Container 入門 |
| icon | 使用的圖示名稱 | material-symbols:casino-outline |
| createTime | 建立時間（YYYY/MM/DD HH:mm:ss） | 2025/10/03 15:04:00 |
| permalink | 以 `/Wwise/course/<slug>/` 結構結尾需 `/` | /Wwise/course/random-container/ |
| order | 顯示排序（整數） | 5 |

要求：
- 不可重複定義相同 key。
- 只出現一組 `---` frontmatter 區塊。

## 2. 文章結構（順序固定）
1. `::: tip` 區塊：1~3 行，說明「為什麼要學 / 價值」。
2. `## 🎯 本節你會收穫`：5±2 條清單，動詞開頭，避免冗長句。
3. 主內容：依主題分節，標題層級從 `##` 開始，不使用 `#`。
4. 常見錯誤 / Debug 區（若主題適用）。
5. 測試 / 驗證 / Debug / 品質檢查清單（至少其一）。
6. `## 🚀 下節預告`（最後一篇改為總結段落，如 `## 🎉 系列總結`）。
7. 結尾祝賀語：以「**🎊 恭喜！」開頭。

## 3. 語氣與文風
| 項目 | 規範 |
| ---- | ---- |
| 口吻 | 教學式、實務導向、直接明確，不賣弄華麗辭藻 |
| Emoji | 功能性（強調分類/狀態），標題可 1 個，不連續堆疊 |
| 段落長度 | 3~5 行為佳，過長需拆分 |
| 列表 | 動詞或名詞開頭，保持語法平行 |
| 表格 | 優先用於對照、流程、錯誤 → 解法 |
| 代碼塊 | 僅示意結構或命令，不內嵌過度無關內容 |

## 4. 命名規則
| 類型 | 規則 | 範例 |
| ---- | ---- | ---- |
| 檔名 | `NN.<主題>.md`（整數 + 點 + 主題，避免空格） | 05.RandomContainer入門.md |
| permalink slug | 小寫 kebab / 可含數字 | /Wwise/course/blend-container/ |
| Event 命名（示例文內） | 動詞_對象 | Play_Footstep |
| Switch Group | PascalCase | SurfaceType |
| Game Parameter | PascalCase | PlayerSpeed |

## 5. 表格式寫法建議
- 第一欄行寬控制簡短，避免整欄都是長句。
- 可用「| 問題 | 根因 | 解法 |」統一錯誤排查形式。

## 6. 檢查清單（Checklist）
- 標題含 `✅` 或文字「檢查清單 / 品質檢查清單」。
- 條目採 `- [ ]` 前綴，語意簡潔。
- 不混入結尾祝賀語。

## 7. 下節預告規則
| 範圍 | 規則 |
| ---- | ---- |
| 非最後一篇 | 一定要有「下節預告」段落，指出核心價值與銜接邏輯 |
| 最後一篇 | 改用「系列總結」，不可再出現「下節預告」字樣 |

## 8. 常見錯誤（避免）
| 類型 | 描述 | 解法 |
| ---- | ---- | ---- |
| 多個 frontmatter | 檔案中重複 `---` 領域 | 合併為一個並移除殘留碎片 |
| 缺 tip | 沒有開頭價值說明 | 補 1~3 行精煉說明 |
| 沒有收穫段 | 缺 `🎯` 區塊 | 依格式補上 |
| Checklist 格式錯誤 | 用 `*` 或數字 | 改用 `- [ ]` |
| 預告出現在最後一篇 | 結尾不應再引導下一節 | 改為系列總結 |

## 9. 自動檢查（腳本）對應規則
| 規則 | 自動檢查 | 備註 |
| ---- | -------- | ---- |
| Frontmatter keys | 會檢查 | 缺少會報錯 |
| 單一 frontmatter | 會檢查 | 多段報錯 |
| tip 區塊存在 | 會檢查 | 搜尋 `::: tip` |
| 🎯 收穫標題 | 會檢查 | 正則 `##\s+🎯` |
| Checklist | 會檢查 | 找含 `✅` 或 `檢查清單` 標題 |
| 下節預告 | 會檢查 | 最後一篇必須無；其他必須有 |
| 結尾恭喜 | 會檢查 | 搜尋 "恭喜！" |

## 10. 建議補強（未自動化）
| 項目 | 原因 |
| ---- | ---- |
| 語氣一致性 | 難以程式判斷語調 | 人工 Review |
| 過度 Emoji | 自動規則易誤判 | 人工把關 |
| 表格欄位過多 | 無法輕易量化 | 人工精簡 |

## 11. 撰寫流程建議
1. 複製上一節成熟模板。
2. 修改 Frontmatter（避免複製錯誤時間與 order）。
3. 先寫 tip + 🎯 收穫，確認定位。
4. 補核心正文（表格優先）。
5. 加錯誤排查與檢查清單。
6. 寫下節預告（或總結）。
7. 跑 `npm run lint:lessons` 確認無誤。

## 12. 範例骨架（可複製）
```markdown
---
title: <標題>
icon: material-symbols:<icon-name>
createTime: YYYY/MM/DD HH:mm:ss
permalink: /Wwise/course/<slug>/
order: <N>
---

::: tip <一句價值>
<再 1~2 行延伸描述，可省略>
:::

## 🎯 本節你會收穫
- ...
- ...

## 一、核心概念
...

## 二、實作步驟
...

## 三、常見錯誤與解法
| 問題 | 根因 | 解法 |
| ---- | ---- | ---- |
| ... | ... | ... |

## 四、測試 / 驗證
...

## ✅ 品質檢查清單
- [ ] ...
- [ ] ...

## 🚀 下節預告：<下一節主題>
簡述下一節價值與銜接。

**🎊 恭喜！你已完成 <本節核心能力總結>！**
```

如需新增規則或讓腳本更嚴格，可在 `scripts/check-lessons.mjs` 增補對應檢查。
