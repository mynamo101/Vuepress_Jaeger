## 一、為什麼需要 Bus？

### 🚦 Bus 就像交通樞紐
想像你是城市規劃師，不可能讓每台車都直接開到目的地，而是設計「幹道 → 支道 → 巷道」的層級。Bus 就是聲音的「交通網絡」。

**生活化比喻**：
- **沒有 Bus**：1000 個音效各自獨立調音量 = 每台車都要單獨指揮
- **有了 Bus**：Music / SFX / VO 分層控制 = 用紅綠燈管理整條道路

### Bus 的核心價值

| 功能     | 範例                      | 價值           |
| -------- | ------------------------- | -------------- |
| 群組控制 | 一次拉低全部 SFX          | 快速迭代調整   |
| 套用效果 | 在 Ambience Bus 加 Reverb | 統一空間感     |
| 分層混音 | Music / VO / SFX 分離     | 清晰度大幅提升 |
| Ducking  | VO 播放時壓低 Music       | 焦點聚焦對話   |

::: warning 🔴 新手常犯的錯誤
直接在每個音效素材上加效果（Insert）→ 後續維護噩夢！
**正確做法**：通過 Bus 統一管理，修改一次全部生效。
:::

## 二、建立你的第一個 Bus 結構

### 🏗️ 推薦的基礎架構
```
Master Audio Bus
  ├─ Music          （背景音樂）
  ├─ SFX            （音效主線）
  │   ├─ Characters （角色相關音效）
  │   ├─ Weapons    （武器音效）
  │   └─ Ambience   （環境音效）
  └─ VO             （語音對話）
```

### 實際操作步驟

1. **開啟 Master-Mixer Hierarchy**
   - Project Explorer → Master-Mixer Hierarchy 標籤

2. **建立主要 Bus**
   - 右鍵 `Master Audio Bus` → New Child → Bus
   - 分別建立：`Music`、`SFX`、`VO`

3. **建立 SFX 子分類**
   - 右鍵 `SFX` → New Child → Bus
   - 建立：`Characters`、`Weapons`、`Ambience`

4. **路由你的素材**
   - 回到 Actor-Mixer Hierarchy
   - 選擇之前建立的 Footsteps 群組
   - 在 Property Editor 中找到 `Output Bus`
   - 設定為 `SFX → Characters`

::: tip 💡 路由檢查技巧
選中任一素材，看 Property Editor 的 Output Bus 欄位，確保不是直接指向 Master Audio Bus。
:::

## 三、Insert vs Send：兩種效果器處理方式

### 🔧 Insert（串聯式）

**工作原理**：效果器直接「插入」訊號鏈，100% 處理訊號。

**適合使用**：
- ✅ EQ（等化器）
- ✅ Compressor（壓縮器）
- ✅ Saturation（飽和度）
- ✅ 需要完全處理訊號的效果

**生活化比喻**：像是給照片加濾鏡，整張照片都會被處理。

### 📡 Send (Aux)（並聯式）

**工作原理**：複製一份訊號送到效果 Bus，再與原訊號混合。

**適合使用**：
- ✅ Reverb（混響）
- ✅ Delay（延遲）
- ✅ 特殊空間效果
- ✅ 需要「乾濕混合」的效果

**生活化比喻**：像是在原聲之外加上回音，你可以控制回音的比例。

### 對比表格

| 類型       | 處理方式            | 適合                      | 不適合           |
| ---------- | ------------------- | ------------------------- | ---------------- |
| Insert     | 直接處理通道訊號    | EQ / Comp / Saturation    | 需要並行混合情境 |
| Send (Aux) | 分流到效果 Bus 混回 | Reverb / Delay / 特殊空間 | 完全取代原訊號   |

## 四、實作：建立你的第一個 Reverb Send

### 🎭 為什麼用 Aux Send 做 Reverb？
- 多個素材共用一個 Reverb（節省 CPU）
- 統一調整空間感（修改一次全部生效）
- 可以對 Reverb 單獨做 EQ 處理

### 詳細操作步驟

#### Step 1: 建立 Aux Bus
1. 在 Master-Mixer Hierarchy 中
2. 右鍵 `Master Audio Bus` → New Child → **Auxiliary Bus**
3. 命名為 `Reverb_Room`

#### Step 2: 加入 Reverb 效果器
1. 選中 `Reverb_Room`
2. 在 Effects 標籤點擊 `+` 
3. 選擇 `Wwise RoomVerb`（或 `Wwise Reverb`）
4. 設定初始參數：
   - **Decay Time**: 1.2s（房間殘響時間）
   - **Early Reflections**: 30%（早期反射）
   - **HF Damping**: 3000Hz 左右（高頻衰減，避免過亮）

#### Step 3: 設定 Aux Send
1. 回到 Actor-Mixer Hierarchy
2. 選擇 `Ambience` 群組（或特定的環境音效）
3. 在 Property Editor → Positioning 標籤
4. 找到 **Auxiliary Sends**
5. 點擊 `+` 添加 `Reverb_Room`
6. 調整發送量：**10-15 dB**（起步值，後續微調）

#### Step 4: A/B 測試
1. 播放環境音效
2. 在 `Reverb_Room` Bus 上點擊 **Mute** 按鈕
3. 反覆開關，對比：
   - ✅ **好的 Reverb**：增加空間感，聲音更自然
   - ❌ **過量 Reverb**：聲音變糊，失去清晰度

::: warning ⚠️ Reverb 使用警告
**絕對不要**直接在 VO（語音）上加太多 Reverb！
會讓對話變得模糊不清，玩家聽不懂在說什麼。
:::

## 五、初步 Ducking：讓語音突出

### 🎤 什麼是 Ducking？
當重要的聲音（如對話）出現時，自動降低背景音樂的音量，確保玩家能清楚聽到對話。

**生活化比喻**：像是電視新聞主播說話時，背景音樂會自動變小聲。

### 設定 Ducking 的步驟

#### Step 1: 設定被壓低的對象（Music Bus）
1. 選中 `Music` Bus
2. 在 Property Editor → HDR 標籤
3. 找到 **Ducking** 區域
4. 點擊 `+` 新增 Ducking 設定

#### Step 2: 選擇觸發源（VO Bus）
1. 在彈出的視窗中選擇 `VO` Bus
2. 設定參數：
   - **Volume**: `-4 dB` 到 `-6 dB`（壓低多少）
   - **Fade Out**: `100-200ms`（多快壓低）
   - **Fade In**: `300-800ms`（多快恢復，建議較慢）

#### Step 3: 測試效果
1. 播放背景音樂
2. 觸發一個對話 Event
3. 觀察音樂是否平滑降低、對話結束後平滑恢復

::: tip 💡 Ducking 參數建議
- **快速對話**：Fade In 300-500ms
- **長篇對話**：Fade In 500-800ms
- **不要設定太極端**：-10dB 以上會讓音樂完全消失，破壞氛圍
:::

## 六、Loudness 與動態範圍管理

### 🔊 什麼是 Headroom？
**Headroom** = 你的訊號峰值與 0dBFS（數位滿格）之間的安全距離。

**為什麼需要？**
- 避免爆音失真（Clipping）
- 為後續處理留空間
- 保持動態範圍（大小聲對比）

### 推薦策略
- **不追求全程最大聲**：留 **-6dBFS** 的 Headroom
- **優先級排序**：VO 清晰 > SFX 存在感 > 音樂包覆感

### 各類聲音的層級建議

| 類型                    | 期望主觀層級 | 注意事項                   |
| ----------------------- | ------------ | -------------------------- |
| Dialogue / 關鍵 VO      | 最清晰       | 避免過度 Reverb            |
| 互動 SFX（武器 / 技能） | 次高         | 避免掩蓋 VO 頻段（2–4kHz） |
| Ambience                | 支撐層       | 不與主體搶中頻             |
| Music                   | 情緒底層     | Duck 後仍保留氛圍          |

## 七、混音迭代工作流程

### 🔄 推薦的五步驟流程

#### 1️⃣ 確保路由正確
檢查所有素材都已正確路由到對應的 Bus，沒有直接輸出到 Master。

#### 2️⃣ Solo 單獨預聽
逐一 Solo 各個 Bus，修正：
- 過尖的高頻（用 EQ 削減 8kHz 以上）
- 過糊的低頻（用 High Pass Filter 切掉 80Hz 以下）

#### 3️⃣ 全部同播檢查衝突
播放所有聲音，找出「搶戲」的頻段：
- Music 與 VO 都很厚重 → 在 Music 上削減 2-3kHz
- SFX 與 Ambience 混濁 → 分別用 EQ 做頻段分工

#### 4️⃣ 適度加入空間效果
用 Aux Send 加入 Reverb / Delay，**從少量開始**（10-15%）。

#### 5️⃣ Ducking 測試
播放完整場景，確認對話觸發時音樂平滑降低。

## 八、常見錯誤與避坑指南

| 🔴 問題             | 🔍 根本原因       | ✅ 修正建議                             |
| -------------------- | ------------------ | --------------------------------------- |
| 所有聲音都直接掛效果 | 沒建立 Bus 分層    | 建立 Music / SFX / VO / Ambience 主幹   |
| Reverb 糊成一片      | 用 Insert 在素材上 | 改用 Aux Send + 在 Return 上做 EQ 清理  |
| VO 被音樂淹沒        | 沒 Duck 或中頻衝突 | 加 Duck -4~-6dB + Music 2~3kHz 輕微削減 |
| 音量忽大忽小         | 沒保留 Headroom    | 先整體降 3~6dB 再重新調整平衡           |
| 調整反覆沒有重點     | 無檢查清單         | 先檢查路由與分類，再做細節調整          |
| Bus 結構過度複雜     | 過早優化           | 先建立 3-4 層基礎結構，後續再細分       |

## 九、測試驗證清單

### 🧪 快速驗證你的混音品質

| 測試項目   | 操作方式        | 合格標準                       |
| ---------- | --------------- | ------------------------------ |
| 分層獨聽   | Solo 各個 Bus   | 無爆音 / 失真 / 嚴重頻段缺失   |
| 全混播放   | 全部播放 30 秒  | 無單一 Bus 過份突出            |
| Duck 語音  | 播放 VO 片段    | Music 平滑下降後自然回復       |
| Reverb A/B | 關閉 / 開啟 Aux | 加 Reverb 後更有空間感而非更糊 |
| 峰值觀察   | 監看輸出電平    | 保留 -3 ~ -6dBFS 頭部空間      |

## 💡 常見問題 FAQ

| 🤔 問題                     | 🔍 可能原因          | ✨ 解法                                 |
| ---------------------------- | --------------------- | --------------------------------------- |
| Reverb 聽起來很假            | 參數設定不當          | 降低 Decay Time，增加 Early Reflections |
| Ducking 恢復太突兀           | Fade In 時間太短      | 將 Fade In 調整到 500-800ms             |
| 所有聲音都很小聲             | 沒有正確設定 Bus 音量 | 檢查各 Bus 的 Volume 設定，適度提升     |
| 不知道該削減哪些頻段         | 缺乏頻段分析工具      | 使用 Spectrum Analyzer 或頻譜分析插件   |
| Bus 結構建好後不知道如何維護 | 缺乏文檔記錄          | 建立簡單的 Bus 路由圖文檔，團隊共享     |
