## 一、Event 是什麼再複習
Event = 程式端呼叫的「語意行為」。不要在名稱中硬塞素材細節（例如音量、版本號）。

### 🏷️ 命名範例對照表

| 📝 範例 | 🟢/🔴 評判 | 💬 說明 | 💡 建議改法 |
| ---- | ---- | ---- | ---- |
| `Play_Footstep` | 🟢 很好 | 語意明確、簡潔 | - |
| `Play_Footstep_Stone` | 🟡 可以但... | 若用 Switch 更好 | `Play_Footstep` + SurfaceType Switch |
| `Play_explosion_small_v2` | 🔴 避免 | 包含實作細節，不利維護 | `Play_Explosion_Small` |
| `PlayFootstepGrassLoop` | 🔴 不好 | 沒有底線分隔，難讀 | `Play_Footstep_Grass_Loop` |
| `sfx_button_click_01` | 🔴 不好 | 沒有 Play 前綴，不知道行為 | `Play_UI_Button_Click` |

::: tip 🎯 命名黃金法則
1. **動詞開頭**：Play_ / Stop_ / Pause_ / Resume_
2. **語意分層**：大分類 → 小分類 → 特定事件
3. **避免技術細節**：版本號、音量值、檔案格式
4. **團隊一致**：全團隊使用相同的命名慣例
:::

## 二、常見 Event 類型
- Play：播放（最常用）
- Stop：立即或淡出停止
- Pause / Resume：暫停與回復（常用於音樂 / 長循環環境）
- Set State / Set Switch（進階會談）

## 三、建立多個腳步事件練習
1. 建立 `Footsteps` Actor-Mixer Group
2. 建 5 個腳步聲 Sound SFX 放入 Random Container（暫不調整細節）
3. 建立 Event：`Play_Footstep`
4. 測試播放 10 次，確認不完全重複（後面課程再調 No Repeat）

## 四、Soundcaster 測試
1. 打開 Soundcaster Layout
2. 將 `Play_Footstep` 拖入一個 Cue Slot
3. 可以快速模擬多次觸發與組合其他事件（例如 UI_Click）

::: tip 為什麼不用一直重建 SoundBank？
在 Authoring 內測試（Event Viewer / Soundcaster）不需要重新生成；只有遊戲端載入才需要生成。
:::

## 五、避免 Event 炸裂的策略
| 不良案例 | 改善方式 |
| -------- | -------- |
| Play_Footstep_Stone / _Wood / _Metal | 改用 Switch：Play_Footstep + SurfaceType |
| Play_UI_Click_Small / _Big | 一個 Event，差異用多 Layer 或音量調整 |
| Play_Sword_Slash / Play_Sword_Slash2 | Random 容器處理隨機變化 |

## 六、與程式對接的最小 JSON 列表示例（概念）
```json
[
  { "event": "Play_UI_Click" },
  { "event": "Play_Footstep" }
]
```
實際對接會依據使用的中介（如 Unreal Integration / Unity Integration）自動產生 ID 對照，不必手寫。
