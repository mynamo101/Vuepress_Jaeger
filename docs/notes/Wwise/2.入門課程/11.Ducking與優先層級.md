## 🎯 本節你會收穫
- 🔻 理解 Ducking（Sidechain）運作原理與核心參數
- 🎤 Dialogue 壓低 Music 的標準實作與調校範圍
- 🔔 UI / 提示音與環境聲的輕度區隔策略
- 🧱 Priority / Virtual Voice 聲音資源競爭管理
- 🧯 常見錯誤（泵動、過度壓扁、優先丟失）排查

## 🧠 為什麼需要 Ducking？
玩家一次專注通道有限，資訊同時堆疊會疲勞。透過在「關鍵語音 / 提示期間」暫時降低背景層存在感，維持清晰度與層次。

## 🎤 Dialogue 壓低 Music（典型案例）
步驟：
1. Music Bus 設為被 Duck（受 Sidechain）
2. Dialogue Bus 設為 Duck 發送端（Sidechain Trigger）
3. 初始設定建議：Attack 40–80ms / Release 500–800ms / Depth -5 ~ -7dB
4. 聽感微調：避免語音一開就瞬間「抽走」背景；尾端回復要自然不彈起

## 🔔 UI 提示壓環境（輕度）
| 類型             | 建議 Depth | 說明                |
| ---------------- | ---------- | ------------------- |
| 任務/重大通知    | -3 ~ -5dB  | 短暫讓提示浮現      |
| 一般按鈕 / Hover | 0dB        | 不需 Duck，保持輕量 |

可選：將 UI 分成 Critical / Normal 兩個 Bus，只對 Critical 發送 Duck。

## 🧱 Priority 與 Virtual Voice
| 名詞          | 定義                          | 實務策略                        |
| ------------- | ----------------------------- | ------------------------------- |
| Priority      | 聲音資源緊張時排序            | 角色 > 關鍵互動 > UI > 環境尾巴 |
| Virtual Voice | 保留邏輯（RTPC/計時）但不混音 | 適合遠距環境、長尾聲            |

設定上限：例如 SFX 最大 64 Voices；溢出時先虛擬低 Priority 物件。

## 🧯 常見錯誤與修正
| 問題                  | 根因                  | 修正                           |
| --------------------- | --------------------- | ------------------------------ |
| 壓縮泵動（呼吸感）    | Attack / Release 太短 | 延長 Release 600ms+ 或調緩曲線 |
| 語音剛出瞬間背景全退  | Attack 太快 (<=10ms)  | 增至 40–60ms                   |
| Dialogue 結束背景彈起 | Release 過短          | 拉長 500–800ms 漸回            |
| 背景一直被壓很扁      | Depth 過深            | 調回 -3~-8dB 區間              |
| 重要聲被吃掉          | Priority 未設定或過低 | 提升 Bus / 物件 Priority 等級  |

## 🧪 測試與驗證
1. 建測試場景：同時播放音樂、環境、UI、語音
2. 播放 Dialogue → 觀察 Music 下潛是否平滑
3. 連續多段語音 → 是否造成背景忽明忽暗（如有 → 延長 Release 或加最小 Depth Gate）
4. 模擬極端：大量環境聲 + 爆裂特效 → 看是否錯丟關鍵聲（Profiler / Voice Monitor）
